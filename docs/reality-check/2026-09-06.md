# Comb next steps, 2026-09-06

Comb has a useful correctness prototype, but Core alpha and Pheromone cloud alpha are unfinished. Build on immutable objects, conditional refs, and the basic Log. Finish retry semantics and sustained operation before expanding into Trees, Volumes, or hosting.

This assessment covers Comb at `8674fe4`, also the remote main branch when checked. The latest implementation commit is `8428831`, Slice 5. The August 25 scale audit still describes this implementation. Its benchmark numbers were not rerun, and its claims about Pheromone's current implementation were not independently checked.

## What to retain and rework

| Area | Disposition | Reason and scope |
|---|---|---|
| Immutable objects, conditional refs, basic Log | Build on | The implementations and drills provide a useful base. Preserve their object-before-publication ordering. |
| Append retries and leadership | Rework | Add operation identity, recover committed outcomes, and give writer sessions explicit fences and renewal. |
| Sustained Log storage and replay | Rework | Bound manifests and reads. Automate compaction and make retention release obsolete references. |
| GC and journal completeness | Rework | Protect reader roots, abort destructive GC when marking is incomplete, and close missing logical history. |
| Trees, Volumes, hosting | Defer | These depend on Core contracts that remain unfinished. Nothing assessed warrants discarding the project. |

## Ranked next moves

1. Make retries safe. Add durable operation IDs to Core mutations and append admission, with a defined deduplication window. A lost reply followed by the same operation must return its original result without another generation or sequence allocation. Replace the misleading C4 expectation and add L2 fault injection exactly after manifest publication. This closes claim 5. It is a focused correctness slice and should precede automatic retries.
2. Bound storage growth and protect readers. Add automatic compaction thresholds, segment merging, and physical retention. Add pins or a generation barrier and protected-root revalidation before enabling automatic deletion. Abort deletion if any required traversal read fails. Today, a failed manifest read can prevent the sweeper from marking its children while deletion still proceeds. Verify manifest size, retained bytes, and a reader holding an old manifest during compaction and GC. This closes claims 4 and 8 and is the largest immediate work item.
3. Bound replay and harden long-running operation. Define a reusable Log interface and position type, add `read(position, max)` with indexed or range-based reads, and recover followers from transient failures and stale manifests. Preserve explicit `Trimmed` results rather than silently skipping events. Add writer-instance identity, explicit fencing, an idle lease-renewal loop, and deterministic time-based takeover tests. This closes claims 6 and 7 across separate reader and writer slices.
4. Close the remaining Core alpha contracts and prove one Pheromone integration. Finish pins, scoped journal behavior, and the other Phase B ref conventions. Move reusable Log behavior out of the CLI crate as the consumer interface becomes concrete. Check Pheromone's current `TrailLog` readiness before scheduling its adapter work. Run append, follow, replay, takeover, retry, compaction, and retention end to end on one MinIO-backed partition, then S3. Add repeatable CI gates and publish current measurements. This addresses claims 9 and 10 and tests the first real consumer.

Start with one partition. The specification makes partitions optional in Phase C. The August audit's three-partition, 50k-events-per-second exercise is a later scale target, not the first integration gate. After the cloud Log passes its acceptance criteria, continue to Trees and repository generations, native Volumes, and hosted beta in the specified order. The portable object-backed Volume remains behind its measurement gate.

## Acceptance evidence for the next milestone

Use an agreed representative sustained workload and record manifest bytes, stored bytes, append p50 and p99, replay memory, and follower lag. Inject leader death, lost replies, backend outages, and stale readers during compaction. Require zero acknowledged-event loss, retry deduplication, bounded replay memory, and storage growth consistent with retention. Do not substitute peak throughput from a short run for this evidence.
